# Unit Test Catalogue

This document has one entry per unit test file and says what that suite holds. Look a file up here before you add a case, and add or update its entry in the same change when a suite is created or restructured.

## Test Files

Every file is under `tests/`; the captured responses the suites read are in `tests/fixtures/` — responses captured from the running backend, plus the contract manifest

### Selection, arrangement and stored state

- **`selection_store.test.ts`** — the facade over the main link's market and the chart's timeframe: brought back from the arrangement, a new broker clearing the symbol and keeping the timeframe, resetTimeframe, isReady
- **`timeframe_store.test.ts`** — load-once cache, minutesFor lookup, error handling, loading flag
- **`bars_store.test.ts`** — coverage validation, window calculation, a timeframe outside the coverage REPORTED and the selection left alone, error handling
- **`context_store.test.ts`** — the main link always there, the cascades (a new run takes the narrowing and the mark with it, a narrowing keeps the mark and drops duplicates, a new broker clears the symbol), one scenario in focus — a click moves it, a second on the same one clears it, and a restore that applies stored links without cascading
- **`arrangement_store.test.ts`** — how a chart's layers were arranged, kept field by field — an unknown layer or option, an opacity of the whole or below the least one never copied — and written back; the stored selection restored into the context on creation and every change written back, a damaged entry reconciled rather than trusted, another schema removed rather than converted, an unreadable entry the same as none, a cleared bar kept apart from an untouched one across a reload, and where each panel stood kept across a reload — a place naming nothing to stand beside, or a side that does not exist, dropped; the run chart's unit and timeframe written back with the run they were chosen for, and reconciled field by field; and a stored narrowing of several reconciled to one scenario in focus; and each panel's own view: none from an entry written before it, kept across a reload with what is not one dropped, an entry left empty removed, the same view writing nothing, only the views of panels still known kept; and the rows a panel kept for one run, without a run none, each list deduplicated with the newest kept and cut to its cap
- **`tab_storage.test.ts`** — what a browser tab keeps for itself: its own entry read before the one any tab saved last, a NEW tab starting from the last one saved and keeping it as its own — starting with nothing kept too — so another tab's later write never reaches it, every write to both and a removal from both, the shared entry still read where the tab's own storage is blocked, and blocked storage the same as none, never a throw
- **`use_run_binding.test.ts`** — the run the reader had open brought back with its narrowing and its mark, a run gone from the index named, the index alone where nothing was open, and a run picked while the stored one is still loading kept — its late answer discarded
- **`use_deployment_binding.test.ts`** — the deployment brought back, and one the ledger no longer lists named
- **`use_chart_binding.test.ts`** — a timeframe the symbol has no coverage for cleared, a covered one kept
- **`use_facet_state.test.ts`** — an untouched bar on its defaults and storing nothing, narrowing, search and sort brought back, a CLEARED bar kept cleared rather than given its default back, and the scope: a narrowing stored for another run dropped with its sort kept, the same run restored, and a run change under a mounted bar dropping the narrowing and storing the new scope
- **`use_chart_layers.test.ts`** — a chart's layers arranged by its dock id: read front first; a hidden layer, a fainter one and a switched option kept with the chart's own view beside what it held; a layer moved one place and no further than either end; an opacity held between the least one and the whole; nothing kept once the layers are back as the chart has them, and nothing to arrange without a chart
- **`use_panel_view.test.ts`** — a fold kept under the panel its host names, found again by a second mount under the same panel and only there, nothing kept for a fold set back to its default, and without a host a view that lives for one mount and is stored nowhere; and rows kept for the run on show, none of them found under another run, replaced whole when another run writes, nothing kept for a key set back off or where no run is on show

- **`settings_store.test.ts`** — per-field reconciliation (unknown key dropped, missing key defaulted, out-of-range refused), the schema-version discard, setters that ignore rather than clamp, and the display subset handed to panels; an entry of another version removed rather than left behind
